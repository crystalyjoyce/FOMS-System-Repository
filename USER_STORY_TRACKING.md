# FOMS User Story Tracking Board

> This document acts as your checklist (notes) for the entire Finance Operations Management System (FOMS) Capstone project. It tracks the progress of all 49 user stories from your Product Backlog.

## Module 1: Authentication & Security 🔐
- ✅ PB-001: USER STORY: As an authorized user, I want to log in securely using my registered credentials so that I can access the FOMS system.
- ✅ PB-002: USER STORY: As a user, I want to securely log out from the system so that my account remains protected after use.
- ✅ PB-003: USER STORY: As a system user, I want unauthorized access restricted and role-based permissions enforced so that finance records remain protected.
- ✅ PB-004: USER STORY: As a user, I want to view my profile information and maintain a secure session so that I can verify my account details safely.

## Module 2: Client Management & Rates 🏢
- ✅ PB-005: USER STORY: As an authorized finance user, I want to manage client account information so that client records are centralized.
- ✅ PB-006: USER STORY: As an authorized user, I want to search client accounts so that I can quickly find client records.
- ✅ PB-007: USER STORY: As an authorized user, I want to manage client-specific billing rates so that invoices follow approved rates.

## Module 3: Operations Intake & Validations 🚚
- ✅ PB-008: USER STORY: As an authorized user, I want to record waybill or POD details so that completed deliveries can be used for billing.
- ✅ PB-009: USER STORY: As an authorized user, I want to validate original POD or waybill records so that billing proceeds only with valid documents.
- ✅ PB-010: USER STORY: As an accounting user, I want validated POD or waybill records to be used as the billing basis so that invoices are properly supported.
- ✅ PB-011: USER STORY: As an authorized user, I want to record certified true copy documentation when the original POD or waybill is missing but approved.

## Module 4: Invoicing 🧾
- ✅ PB-012: USER STORY: As an accounting user, I want to create invoices from validated records so that billing can be processed accurately.
- ✅ PB-013: USER STORY: As an accounting user, I want the system to calculate billing charges so that computations are accurate.
- ✅ PB-014: USER STORY: As an accounting user, I want the system to compute the invoice total amount so that the correct billing amount is shown.
- ✅ PB-015: USER STORY: As an accounting user, I want to apply different billing schedules so that client billing arrangements can be followed.
- ✅ PB-016: USER STORY: As a Head Accountant, I want to review and verify invoices before finalization so that billing records are checked.
- ✅ PB-017: USER STORY: As a Head Accountant, I want only verified invoices to be finalized so that unchecked invoices are not released.
- ✅ PB-018: USER STORY: As a finance user, I want to monitor invoice status so that I can track billing progress.
- ✅ PB-019: USER STORY: As a finance user, I want invoice status to update automatically so that records stay current.

## Module 5: Accounts Receivable & Aging 📊
- ✅ PB-020: USER STORY: As a finance user, I want approved and sent invoices recorded as Accounts Receivable so that receivables can be monitored.
- ✅ PB-021: USER STORY: As a finance user, I want to monitor Accounts Receivable per client so that unpaid invoices and balances are visible.
- ✅ PB-022: USER STORY: As a finance user, I want to track outstanding balances so that client payment obligations are monitored.
- ✅ PB-023: USER STORY: As a finance user, I want unpaid invoices categorized by due date, payment status, and aging status so that follow-up can be prioritized.
- ✅ PB-024: USER STORY: As a finance user, I want weekly aging monitoring so that Accounts Receivable records can be reviewed regularly.
- ✅ PB-025: USER STORY: As a finance user, I want due dates computed based on the standard 30-day payment term so that deadlines are consistent.

## Module 6: Payment Recording & Verification 💳
- ✅ PB-026: USER STORY: As a finance user, I want to record client payments so that payment transactions are documented.
- ✅ PB-027: USER STORY: As a finance user, I want each payment linked to a specific invoice so that payments are properly matched.
- ✅ PB-028: USER STORY: As a finance user, I want invoices marked as Paid only after full payment so that payment status is accurate.
- ✅ PB-029: USER STORY: As a finance user, I want incomplete payments not to mark invoices as Paid so that records remain correct.
- ✅ PB-030: USER STORY: As authorized finance personnel, I want to validate payment transactions so that only confirmed payments are recorded.
- ✅ PB-031: USER STORY: As authorized finance personnel, I want to confirm that payment entered the company account before recording it officially.
- ✅ PB-032: USER STORY: As a finance user, I want to record payment reference details so that payment documentation is complete.

## Module 7: SpeedPay Digital Payments 🚀
- ✅ PB-033: USER STORY: As a client, I want to select an unpaid invoice in SpeedPay so that I can submit payment details for validation.
- ✅ PB-034: USER STORY: As a client, I want to choose a simulated payment method so that I can proceed with payment simulation.
- ✅ PB-035: USER STORY: As a client, I want to upload proof of payment so that finance can validate my payment.
- ✅ PB-036: USER STORY: As a client, I want to submit payment details so that finance personnel can review and validate them.
- ✅ PB-037: USER STORY: As a client or finance user, I want to view SpeedPay payment status so that I know if the payment is pending, validated, or rejected.

## Module 8: Official Receipts 📝
- ✅ PB-038: USER STORY: As a finance user, I want to record official receipt details after payment validation so that receipts are documented.
- ✅ PB-039: USER STORY: As a finance user, I want receipts linked to invoices and payments so that documentation is traceable.

## Module 9: Reports & Dashboard 📈
- ✅ PB-040: USER STORY: As a finance user, I want to generate financial reports so that finance records can be reviewed.
- ✅ PB-041: USER STORY: As a finance user, I want to generate Aging of Accounts reports so that receivables can be monitored.
- ✅ PB-042: USER STORY: As a finance user, I want to generate invoice and collection reports so that billing and payment summaries can be reviewed.
- ✅ PB-043: USER STORY: As a finance user, I want to export financial reports so that they can be used for documentation and review.
- ✅ PB-044: USER STORY: As a finance user, I want to view dashboard summaries so that I can monitor invoices, balances, and payments quickly.
- ✅ PB-045: USER STORY: As a finance user, I want to view client billing history so that I can review invoices, balances, and payment status.
- ✅ PB-046: USER STORY: As a finance user, I want to see accounts near due date so that early follow-up can be done.

## Module 10: Audit Trail & Traceability 🔎
- ✅ PB-047: USER STORY: As a finance reviewer, I want important user activities recorded so that actions are traceable.
- ✅ PB-048: USER STORY: As a finance reviewer, I want audit trail details stored so that accountability is maintained.
- ✅ PB-049: USER STORY: As a finance reviewer, I want financial record changes tracked so that record history is traceable.
